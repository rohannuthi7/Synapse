Food for Thought #1: Since xi is either 1’b0 or 1’b1, a dark cell adds no value. 
Thus, using logic to compute multiplies and sums with it is pointless and takes additional space on the FPGA that could otherwise be avoided. 
Software could keep only the lit cells and send the weights that correspond to those lit cells. 
Since ‘1’ is implied, and 1 * a = a, having a pair {cell index, weight} would let it merely take weights into memory and load those. 
Then, it would compute sums using a hierarchical adder system from L0-L5 (6 levels, just like now). 
This would prevent the need for dedicated hardware to multiply units and division by 64. 
Since dividing by 64 does not change the winner, since a/64 vs. b/64 … vs. j/64 is equivalent to a vs. b … vs. j, there’s no need for a hardware division unit. 

The L0-L5 tree does not shrink. It’s meant for 64 inputs, and theoretically 64 cells could be lit, so contracting that is counterintuitive and risky. 
However, the hierarchical adder can work nonetheless by using hardwired ‘0’ for unused inputs. 
The logic becomes shakier when having an odd number of lit cells, as it’s intended to handle an even 64 inputs in theory. 
The sparse list is a real contraction, and the design is the whole dot product for a reason.
