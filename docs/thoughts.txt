Food for Thought #1: Each cell is an unsigned brightness, 0 through 255, multiplied by a signed 8-bit weight. A dark cell still adds nothing, because brightness 0 times a weight is 0. A partly bright cell adds part of the weight, so the product is a real multiply. Sending only the lit cells, or a pair {cell index, weight}, assumed every kept cell was 1. That assumption does not survive an 8-bit brightness.

The L0-L5 adder tree still has 64 inputs, one product per cell. Unused inputs are hardwired 0. Dividing the ten scores by 64 does not change the winner, so there is no division in the datapath. The weights stay on the FPGA after the first load, and each later picture is 64 brightness bytes. The design keeps the whole dot product.
