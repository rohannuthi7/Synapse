1. Since x(i) is either 1'b0 or 1'b1, a dark cell adds nothing. Software could keep only the lit cells and send the weights that sit on those cells. The 1 is implied, so the pair is (cell index, weight), and the FPGA just adds the weights it receives. No multiply, and no division by 64. Dividing every score by 64 would not change the winner.

Seventeen lit cells is not seventeen weights. Each lit cell has one weight per digit, so 17 × 10 = 170 weight bytes. Sending every weight plus the 8-byte picture is 640 + 8 = 648 bytes. Against that, 170 is the smaller message.

It is the smaller message only when the weights are sent again on every frame. The stored map is smaller still. Load all 640 weights once. After that, each new picture is 8 bytes, and the chip already knows which weight belongs to which cell. 170 bytes every frame costs more than 8.

The L0–L5 tree does not shrink with the list. It is built for 64 inputs: 32 adders, then 16, 8, 4, 2, and 1. Seventeen weights use that tree only if the other 47 inputs are filled with 0 on the chip. The adders left off the wire are still in the hardware.

The match between a lit cell and its weight is the step the stored grid was built to do. Doing that match in software turns the FPGA into an adder for a bag of numbers. We kept the full picture and the full weight maps. The sparse list is a real contraction, and this design is the whole dot product on purpose.
